# Проверка MVP

## UI и дополнительные интеграционные проверки

- Обновлённый backend-набор: 27 тестов прошли на целевых FastAPI 0.119.1, Pydantic 1.10.26 и Rocketry 2.5.1, `pip check` без ошибок. Покрытие с учётом ветвей — 91%. Четыре пропуска: live opt-in и три браузерных теста без Playwright в venv.
- Добавлены полные проверки сохранения сегодняшнего горизонта при 503, пустом ответе и некорректном JSON за завтра. При потере источника повторное обновление возвращает 503, снимок не меняется и из него продолжает строиться тот же план.
- Проверены доставка HTML/JS/CSS и синтаксис JavaScript (`node --check`). Ресурсы включены в package-data, frontend не требует сборки или внешних CDN.
- Playwright: настоящий Chromium + Uvicorn, сохранённый снимок → отчёт → детализация → JSON; демо и пересчёт с нулевой мощностью; отказ обновления с сохранением отчёта. Синтетические цены в браузерных тестах явно помечены. Команда запуска — в README.
- Локальный Chromium не запустился в сетевой песочнице (`setsockopt: Operation not permitted`); попытка запуска с сетевым доступом была прервана. Браузерные проверки подготовлены для CI, но их успех пока не подтверждён. Скриншоты сохраняются в `state/browser/` и артефакте CI.

Ни один из этих сценариев не обращается к SolaX Cloud и не управляет оборудованием.

## Получение данных: проверка всей цепочки

```bash
python -m unittest tests.test_e2e -v
GORDPOOL_LIVE_E2E=1 python -m unittest tests.test_e2e.PricePipelineTests.test_live_nordpool_snapshot_restart_and_plan -v
```

Первый запуск проверяет цепочку HTTP-ответ Nord Pool → настоящий парсер → обновление через API → JSON на диске → чтение снимка новым экземпляром приложения → план из сохранённых цен. Только внешний HTTP-ответ подменён через MockTransport; парсер, хранилище и оптимизатор работают как в приложении. Проверяется совпадение цен и границ интервалов плана с полученными данными.

Второй запуск обращается к настоящему Nord Pool без подмен. Недоступный источник приводит к провалу теста, а не к пропуску. `state/e2e-live.json` содержит статус, HTTP-ответ API, а при успехе — время загрузки, число интервалов, первый/последний интервал, весь снимок и план. Предупреждение об отсутствии завтрашних цен допускается: проверяется весь доступный горизонт. API в обеих проверках вызывается через ASGITransport; запуск Uvicorn, TCP и Rocketry этими тестами не проверяется.

В GitHub Actions: вручную запустить workflow **Python planner** с параметром `live_e2e=true`. Отдельное задание сохраняет отчёт как артефакт `nordpool-live-e2e`, включая случай ошибки. Обычные PR-проверки не зависят от доступности Nord Pool.

Результат 2026-10-28: 26 тестов, 24 прошли, 2 пропущены (Rocketry и live opt-in). Отдельный явный запуск live-теста **прошёл** в 10:13 Europe/Riga после предоставления команде сетевого доступа. Первый запуск в сетевой изоляции вернул 503; это не была ошибка доступности самого Nord Pool.

Получено 96 интервалов LV за торговый день 28 октября, цены 11.01–345.87 EUR/MWh. Обновление и расчёт плана вернули HTTP 200; план содержит 60 текущих/будущих интервалов. Сохранение и чтение новым экземпляром приложения проверены. Данные за 29 октября не получены: ответ не удалось разобрать как JSON (`JSONDecodeError`), предупреждение сохранено вместе с сегодняшним горизонтом. Отчёт: `state/e2e-live.json`. Это проверка с предустановленными FastAPI/Pydantic 2, не подтверждение объявленного набора зависимостей с Pydantic 1. Workflow локально подготовлен, на GitHub не опубликован и не запускался.

## Автоматическая проверка зависимостей

Workflow `.github/workflows/python.yml` устанавливает объявленный набор зависимостей в чистой среде Python 3.11, 3.12 и 3.13, запускает `pip check`, проверяет импорт Rocketry и Pydantic 1, выполняет тесты с покрытием ветвей и офлайн-пример. XML-отчёт покрытия сохраняется как артефакт каждого запуска. Тайм-аут задания — 10 минут.

Это проверяет в том числе существующий тест регистрации настоящего Rocketry: отсутствие пакета приводит к ошибке отдельного шага, а не к незаметному пропуску теста. Workflow ещё не запускался; успешная совместимость пока не подтверждена. Проверки работающего планировщика по реальным часам и живого Nord Pool остаются отдельными задачами.

Повторная локальная проверка 2026-10-27: 24 теста, 23 прошли, тест Rocketry пропущен. Среда использовала FastAPI 0.141.1 / Pydantic 2.13.4. Установка целевых зависимостей заблокирована недоступным сетевым прокси; это не результат проверки целевой комбинации версий.

## Предыдущие проверки

Выполнено в этой среде:

- `python3 -m unittest discover -v`: расчёт, HTTP-адаптер с MockTransport, API через ASGITransport, состояние и временные окна.
- Синтетический сценарий Go: покупка 8 кВт·ч по 2 цента, использование по 30 центов; условный выигрыш 2.24 EUR совпадает с исходным тестом при идеальном КПД и нулевом износе.
- Сравнение с независимым полным перебором маленьких задач; случайные энергетические инварианты с фиксированным seed.
- `python3 -m solax_optimizer examples/request.json`: офлайн воспроизведение работает.

Стандартный `trace --count --missing --summary` до добавления интеграционного smoke-теста показал исполнение 100% учитываемых строк optimizer/api/prices/service и 45% scheduler. Это **не покрытие ветвей** и не доказательство полноты тестов; Rocketry не исполнялся. Команда для нормального отчёта после установки: `pytest --cov=solax_optimizer --cov-branch --cov-report=term-missing`.

Один интеграционный тест регистрации задачи Rocketry явно пропускается, если пакет не установлен. Даже успешная регистрация не заменяет испытание работающего планировщика с часами и остановкой процесса.

Не выполнены: реальный Nord Pool HTTP-запрос; установка и проверка целевых FastAPI/Pydantic 1/Rocketry; работа по реальным часам; управление SolaX; исходный Go test suite. Эти проверки не замещались моками с утверждением о реальной интеграции.
